# OpenClaw Yoda Kit 🧙

Боевые обвязки для [OpenClaw](https://openclaw.ai) — превращают голого агента в
персонального ассистента, который **не выдумывает факты**, видит картинки, слышит
голосовые, читает почту и Telegram, собирает документы — и при этом **не может
натворить дел от вашего имени**.

Всё из этого набора крутится в проде 24/7 у автора (Telegram-ассистент «Йода») и
пережило реальные инциденты, из которых и выросли местные правила безопасности.

## Философия (выстрадано)

1. **Запрет без инструмента = приглашение сочинять.** Бесполезно писать агенту
   «не выдумывай», если у него нет поиска. Сначала дайте инструмент правды
   (research-mcp), потом требуйте честности (config/AGENTS.example.md).
2. **Правила — это просьба. Стена — это отсутствие инструмента.** Фоновый агент
   (heartbeat, кроны) не должен *уметь* отправлять сообщения — иначе однажды он
   «услужливо» ответит живому человеку от вашего имени. У нас так и случилось.
   Шаблон конфига разводит `main` (полный) и `background` (read-only).
3. **Каждая отправка наружу — с копией владельцу.** Любой send с личного аккаунта,
   почты, WhatsApp мгновенно дублируется вам голосом бота. Молчаливых отправок не бывает.
4. **Один вход в Telegram.** Два параллельных подключения одной сессией = Telegram
   убивает ключ авторизации. Всё ходит через один шлюз.
5. **Модели проверяются замером, не верой.** Каталоги провайдеров плавают: модель,
   которая вчера видела картинки, сегодня возвращает пустоту. В ops есть образец
   пробы (зрение + tool-calling) — гоняйте при странностях.

## Быстрый старт

```bash
# 0. Поставьте OpenClaw (https://docs.openclaw.ai) под ОТДЕЛЬНЫМ юзером
#    (не root! у агента не должно быть доступа к вашим деньгам и данным)

# 1. Клонируйте кит
git clone https://github.com/dru4elos/openclaw-yoda-kit
cd openclaw-yoda-kit

# 2. Секреты
cp .env.example ~/.openclaw/.env   # и заполните своими ключами

# 3. Конфиг и правила
#    возьмите config/openclaw.example.json за основу ~/.openclaw/openclaw.json
#    и config/AGENTS.example.md -> ~/.openclaw/workspace/AGENTS.md

# 4. Поиск (самое важное, 2 минуты)
pip install ddgs trafilatura pypdf "mcp[cli]" httpx
cp addons/research-mcp/research_mcp.py ~/.openclaw/
openclaw mcp add research --command $(which python3) --arg ~/.openclaw/research_mcp.py

# 5. Дальше — по README нужных обвязок, каждая ставится независимо
```

Во всех файлах ищите `123456789` (ваш Telegram ID — узнать у @userinfobot),
`@your_yoda_bot` (username вашего бота) и `you@example.com` — замените на свои.

## Второй экземпляр на том же сервере

Нужен отдельный ассистент для другого человека (родственник, коллега) на той же
машине? `install/new_yoda.sh` разворачивает независимый экземпляр:

```bash
sudo ./install/new_yoda.sh yoda2 18790     # пользователь и порт
sudo ./install/deploy_kit.sh yoda2 18790   # скиллы и правила из кита
```

Что он делает: отдельный Unix-пользователь (чужие секреты, `/root` и другие
домашние ему недоступны), свой Node и OpenClaw, свой workspace, свой порт на
loopback, лимиты памяти и CPU через systemd — чтобы новый жилец не придушил
уже работающее.

⚠️ Перед установкой проверьте, что в `/home` не валяются файлы с чужими данными:
права по умолчанию `644` делают их читаемыми для любого пользователя системы.

Личное каждый подключает своё: бот Telegram (новый токен у @BotFather), почта,
календарь. Ключи LLM можно переиспользовать — расход общий.

## Каждая обвязка — отдельно

Не нужен весь кит? Каждая папка в `addons/` самодостаточна: свой README, свои
зависимости, ставится независимо. Минимальный полезный набор — `research-mcp` +
`config/AGENTS.example.md`: уже одно это превращает агента из сказочника в исследователя.

## Чего здесь НЕТ

- Ключей и токенов — только `.env.example` с описанием переменных.
- Контент-студии автора (постинг-агент) — это отдельный закрытый проект.
- Магии: это обвязки вокруг OpenClaw, сам OpenClaw ставится по официальной документации.
