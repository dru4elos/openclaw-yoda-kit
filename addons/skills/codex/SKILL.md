# Codex — программист и аналитик на задачу

Запуск (только проекты из `~/projects`):
`~/.openclaw/workspace/skills/codex/codex_run.sh <репо> "<задача>" [--profile astra|luna|deep] [--timeout 3600]`

- `astra` (по умолчанию) — GPT-6 Astra, рассуждения high: код, статистика, разбор данных.
- `luna` — GPT-5.6 Luna: когда Astra лежит (смотри `~/.openclaw/models_live.json`).
- `deep` — Astra с рассуждениями xhigh: тяжёлые задачи, дольше и дороже. Только когда `astra` не справилась.

## Codex или DeepSeek Harness — выбираешь сама

Решение за тобой: смотри на задачу, сроки и цену. Ниже — ориентиры из опыта, а не правило.
Начала одним агентом и видишь, что он буксует, — переключайся на другого или на другую модель
(`--profile luna`, `--profile deep`, `dsh --model luna`) и коротко скажи доктору, почему.

| Задача | С чего обычно начинать |
|---|---|
| Статистика, анализ таблиц, графики, отчёт по данным исследования | **Codex** |
| Большой код: модуль, рефакторинг, тесты, разбор чужого репозитория | **Codex** |
| Быстрая мелкая задача в коде, черновик | `dsh` (flash, быстрее и дешевле) |
| Правка в одну-две строки | сама, без агента |

## Статистика и данные

- Пакеты уже стоят в `~/rnd-venv`, обёртка кладёт его первым в PATH: pandas, numpy, scipy, statsmodels,
  scikit-learn, lifelines (выживаемость, Каплан — Майер, Кокс), pingouin, tableone («Таблица 1»),
  scikit-posthocs, matplotlib, seaborn, openpyxl, python-docx, jupyter. Сеть у Codex есть: недостающий
  пакет он ставит сам в `~/rnd-venv` (`pip install …`), может качать открытые данные и ходить в API.
- В задаче называй: файл с данными, что сравниваем, какой исход, какой уровень значимости, куда
  сохранить таблицы и графики. Проси скрипт `analysis/*.py`, а не разовые команды: анализ должен
  воспроизводиться одной командой.
- Проверяй сама: цифры в выводе агента сверь с тем, что печатает скрипт при повторном запуске.
  Тест выбран под данные (нормальность, размер групп, парность) — агент должен написать, почему этот.
- Данные пациентов — только обезличенные и только те, что доктор дал для этой задачи. Сырые выгрузки
  в git не кладёшь.

## Как ставить задачу
Одним сообщением: что сделать, где, критерий готовности («`python3 -m pytest` проходит»,
«`python analysis/survival.py` печатает таблицу и сохраняет fig1.png»), чего не трогать.
Коммит и PR/MR делаешь ты сама после проверки.

## После запуска — обязательно
1. Прочитай итог агента и `git diff`: изменения соответствуют задаче, лишнего нет.
2. Сама запусти тесты или скрипт анализа.
3. Ветка, коммит (проверка утечек сработает сама), PR/MR-черновик, обновить STATUS.md.
4. Доктору — коротко: что сделал агент, что проверила ты, какие цифры получились.

## Безопасность
- Песочница `workspace-write`: запись только в репозиторий, `/tmp` и `~/rnd-venv`; сеть есть; ключи в
  команды модели не передаются (`shell_environment_policy.inherit = core`).
- Сеть открыта, значит, в задачу не клади ничего, что нельзя отправить наружу: ни ключей, ни данных
  пациентов, ни кода команды СвойВрача, если задача не про него.
- ⚠️ Песочница ЧИТАТЬ файлы вне репозитория не запрещает. Поэтому: не ставь задач, где агент ходит
  по домашней папке, и никогда не пересылай его сырой журнал — там может оказаться чужое.
- Журналы — `~/projects/.codex-logs/`, итог каждого запуска — файл `.last` рядом.
- Проверка песочницы: `codex_run.sh --check`. Если там `✗ песочница на сервере НЕ включена` или в журнале
  `bwrap: setting up uid map` — команды агента не выполняются вообще. Скажи доктору: нужна одна команда
  AppArmor для bubblewrap на сервере.
