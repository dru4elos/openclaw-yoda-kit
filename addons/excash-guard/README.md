# excash_guard — чтобы автофолбэк моделей действительно срабатывал

## Проблема, которую он решает

Шлюз-агрегатор (у нас excash) при падении модели ведёт себя по-разному:

| режим | что отдаёт |
|---|---|
| без стрима | честный `HTTP 500` |
| **стрим (его и использует OpenClaw)** | **`HTTP 200`, а ошибка — первым кадром SSE** |

Во втором случае OpenClaw видит «ответ без содержимого», трижды повторяет запрос
**к той же модели** (`MAX_EMPTY_ERROR_RETRIES = 3` зашито в коде) и сдаётся с
`LLM request failed`. До резервной модели дело не доходит — ассистент просто
замолкает. Штатный фолбэк с уведомлением `↪️ Model Fallback: …` при этом
исправен, он срабатывает на таймауты и настоящие HTTP-ошибки.

## Что делает

Тонкий прокси на `127.0.0.1:8788`. Всё проксирует как есть, но если поток
начинается кадром ошибки (до единого куска содержимого) — отдаёт наверх честный
`HTTP 502`. Дальше работает штатная машинерия OpenClaw: переход на резерв и
сообщение в чат. Своей логики выбора моделей у сторожа нет.

## Установка

```bash
install -m755 excash_guard.py ~/.openclaw/excash_guard.py
install -m644 excash-guard.service ~/.config/systemd/user/
systemctl --user daemon-reload && systemctl --user enable --now excash-guard
curl -s http://127.0.0.1:8788/_guard/health
```

В `openclaw.json` провайдер смотрит на сторожа:
```json5
models: { providers: { excash: { baseUrl: "http://127.0.0.1:8788", api: "openai-completions" } } }
```
Апстрим задаётся переменной `EXCASH_UPSTREAM` в юните.

## Проверка

`/_guard/health` отдаёт счётчики: `ok` (прошло насквозь), `converted`
(подменено на 502), `upstream_error`. Растущий `converted` — модель у провайдера
лежит, а ассистент при этом продолжает работать на резерве.

## Применимость

Годится для любого OpenAI-совместимого агрегатора, который так же прячет ошибки
в поток. Для провайдера, отдающего честные коды, сторож не нужен.
